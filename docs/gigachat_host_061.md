# Консольный GigaChat Host — 0.6.1

## Назначение

0.6.1 добавляет самостоятельный консольный AI Host. Он запускает существующий локальный MCP Server как дочерний STDIO-процесс и связывает его инструменты с GigaChat Function Calling. GUI, CLI, `application/service.py` и алгоритмы анонимизации не переписываются.

## Установка в Windows

Из корневой папки проекта в PowerShell:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск:

```powershell
.\.venv\Scripts\python.exe src\interfaces\gigachat\host.py
```

Или двойным щелчком по `run_assistant.bat`. Первый запуск попросит путь к папке с CSV, затем GigaChat Authorization key. Ключ вводится скрыто.

Можно передать папку явно:

```powershell
.\.venv\Scripts\python.exe src\interfaces\gigachat\host.py --workspace "D:\datasets"
```

## GigaChat API

Создайте проект GigaChat API в личном кабинете Сбера и получите Authorization key. По умолчанию используется scope `GIGACHAT_API_PERS` и модель `GigaChat-2-Pro`. Для B2B/Corp используйте параметры `--scope`.

Authorization key:

- сначала читается из переменной окружения `GIGACHAT_AUTH_KEY`;
- затем из системного хранилища учётных данных через `keyring`;
- если ключа нет, Host запрашивает его при запуске;
- при согласии ключ сохраняется в системном хранилище ОС, а не в `assistant.json` или Git.

Пример временной установки ключа в PowerShell:

```powershell
$env:GIGACHAT_AUTH_KEY = "ВАШ_AUTHORIZATION_KEY"
.\.venv\Scripts\python.exe src\interfaces\gigachat\host.py
```

Не помещайте ключ в `.env`, `settings.json`, `assistant.json`, исходный код или сообщения Git. После завершения PowerShell временную переменную можно очистить:

```powershell
Remove-Item Env:GIGACHAT_AUTH_KEY
```

Для соединения с GigaChat API Windows должен доверять сертификатам НУЦ Минцифры. Если Host сообщает об ошибке проверки TLS-сертификата, установи актуальные сертификаты по официальной инструкции GigaChat. Не отключай проверку TLS и не используй параметры, разрешающие недоверенные сертификаты. Официальная документация: https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart.

## Рабочая папка и команды

При первом запуске Host спрашивает каталог. Путь сохраняется в локальном `config/assistant.json`, чтобы не вводить его при каждом запуске. Этот файл добавлен в `.gitignore`; он не содержит Authorization key. Согласия на передачу данных и история диалога действуют только до завершения текущей консоли.

Команды:

- `/help` — подсказка;
- `/files` — показать доступные CSV локально, без передачи имён GigaChat;
- `/open <номер или точное имя>` — открыть выбранный CSV локально; модели передаётся только непрозрачный `dataset_id`;
- `/workspace` — показать рабочую папку;
- `/privacy` — посмотреть и отозвать согласия текущей сессии;
- `/clear` — очистить историю диалога и ожидающие подтверждения;
- `/exit` — завершить работу.

Обычные сообщения отправляются GigaChat. Host сам запускает MCP Server; отдельно запускать Inspector или `mcp dev` для обычной работы не требуется.

## Политика передачи данных

Host использует согласия по отдельным категориям:

1. Список имён CSV — отдельное согласие перед передачей GigaChat.
2. Схема и профиль — имена столбцов, типы, роли, QI-группы — отдельное согласие для набора.
3. Агрегированная статистика, корреляции, план и результаты оценок — отдельное согласие для набора.
4. Фактические названия категорий — отдельное согласие для каждого столбца. Инструмент применяет порог частоты не ниже 5 и не выдаёт категории прямых идентификаторов.

Исходные строки, значения ФИО/email/телефонов, выборки строк, таблицы соответствия токенов и абсолютные пути не отправляются GigaChat. В аналитических DTO исключены фактические min/max, значения выбросов и моды. Статистика малых столбцов/пар корреляции подавляется действующим минимальным порогом.

Отказ от передачи агрегатов не блокирует локальную анонимизацию. Host может вернуть модели только факт локального выполнения и относительный путь результата; подробные метрики будут скрыты.

## Подтверждение изменений и запуска

- `preview_profile_changes` не сохраняет профиль. Host показывает локальный diff и спрашивает подтверждение.
- `apply_profile_changes` получает одноразовый токен только от Host после явного локального ответа «да».
- `prepare_anonymization_plan` не запускает алгоритмы и не создаёт выходной файл.
- `execute_anonymization` запускается только после отдельного подтверждения Host. Путь результата обязан быть относительным и оставаться внутри рабочей папки; исходный CSV перезаписать нельзя.
- Срок одноразового подтверждения ограничен, а изменение профиля или исходного CSV после предпросмотра делает его недействительным.

## Ограничения 0.6.1

- Используется только существующий набор статистики, Pearson/Spearman и Utility Evaluation. Произвольный SQL/аналитический DSL не добавлен.
- Одновременно доступна одна активная MCP DatasetSession на один запущенный Host.
- История диалога хранится только в памяти и очищается после выхода.
- Доступ к GigaChat требует отдельного Authorization key и сетевого соединения.
- Результат `ready` относится только к выполненным локальным проверкам и не является абсолютной гарантией анонимности.
